# Context: ubiquitous language

Use these terms with these meanings in code, docs, issues, and prompts. Use the term, not a synonym. If you need a new term, add it here in the same change.

## Product

- **Billy**: the name of the product and of its mascot, Billy the Beaver. Billy is the face of the Personal Agent in the app and on the site. Use "Billy" in copy for the Owner; use "Personal Agent" and "Instance" for the runtime parts. The Cloudflare resources still use the old working name `assistant` until [#159](https://github.com/kacperborowieckb/billy/issues/159).

## People

- **Owner**: the person the agent serves. Each Owner has one Personal Agent and one set of data. Every domain operation runs for exactly one Owner.
- **Operator**: the person who deploys and runs an instance. When you self-host, you are the Operator and the only Owner. In the hosted product, the Operator runs the platform and the customers are the Owners.
- **Owner Id** (`OwnerId`): the stable identifier of an Owner. Storage, traces, usage, and jobs are keyed by it.

## Runtime

- **Instance**: one deployment of `apps/agent` on one Cloudflare account. An Instance has one or more Owners.
- **Edge**: the Worker entry point. It receives Channel traffic, finds the Owner through the Directory, and forwards the Event to that Owner's Personal Agent. It stores no Owner data.
- **Directory**: the store that maps Channel Identities to Owner Ids and records each Owner's status. It also says if Registration is open.
- **Registration**: the way a new Owner is added. A self-host Instance has closed Registration; setup adds the one Owner. The hosted product opens it through `apps/platform`.
- **Personal Agent** (`PersonalAgent`): the Durable Object for one Owner. It holds the Owner's memory, Journal, Inbox, Schedules, and preferences. It sleeps when idle and wakes on any Event.
- **Turn**: one run of the agent loop, from the Events it takes in to the messages and Journal Entries it produces. An Owner message Turn answers one Burst: it takes every Event of the Burst as its input, in arrival order, and is keyed by the first Event of the Burst (the Turn Event), so its Delivery, Turn progress, Conversation, Trace, and metric keep the same key when the Burst grows.
- **Burst**: the pending Owner message Events that one Turn answers, in arrival order. Before the model call, an `AnsweredByTurn` Journal Entry links each other Event of the Burst to the Turn Event, so recovery after a reset settles them from the Delivery of that Turn and does not answer them again. A pending Event that no Turn linked never joins a Turn whose Delivery has started; it waits for a new Burst. A Burst waits for the Quiet Gap after its newest message, and at most `burstMaxWaitMillis` after its first message, before its Turn starts. When an Owner message arrives while the Turn runs, before it sends, the Turn restarts (Restart). The model input labels each message of a Burst of several Events `[Message n of m]`, and a Note captured in that Turn names the message it keeps by that number.
- **Restart**: what an Owner message Turn does when another Owner message arrives before it sends: it drops its answer, sends nothing, writes a restart record (an `EventReceived` Entry with a `restart` field, so an earlier version can read it) and a Trace, and a new Turn starts after the Quiet Gap with every message of the Burst, including the new one, so the Owner gets one combined outcome. Tool calls that finished stay done: the new Turn gets them as completed steps, as after a reset. There are at most `burstMaxRestarts` restarts (default 2) and none once `burstMaxWaitMillis` has passed since the first message; then the Turn sends, and a later message gets its own Turn. A message that arrives after the send gets its own Turn too (decision 0025).
- **Model Turn**: the one module that runs a Turn which calls the model: the step limit, the model call through the Model Gateway, the Trace, the failure branches, the Conversation write, and the metric. The reply Turn, the Scheduled Task Turn, and the Proactive Turn each give it only what differs, and its session kind. It sends through Delivery. It returns a Model Turn result, and the caller settles the Event in the Inbox.
- **Session kind**: the part of a Model Turn that builds its request and commits its result: the main Conversation (an Owner message Turn) or the Side Session (a Scheduled Task Turn or a Proactive Turn). The main Conversation commits the stored form; the Side Session commits the Write-back ([#197](https://github.com/kacperborowieckb/billy/issues/197)).
- **Model Turn result**: the typed result of a Model Turn: `Sent`, `Silent`, `Failed` (with the reason), `SendFailed` (with the reason), or `Superseded`. Each caller matches every case: it completes the Schedule, sends the failure notice, and marks the Event done or failed. The Turn kind has no hooks (decision 0034).
- **Stored form**: the messages that code appends to the Conversation for a finished Owner message Turn, each with its Turn Event id and a row kind: its inputs (the first one starts with its Turn Context Block as it was sent), its completed steps from Turn progress, and the text that the Owner got. One function writes it on every path: a sent Turn, a silent Turn, a failed model call, a failed send, and recovery after a reset. A Side Session, a Reminder, a skipped Scheduled Task, and a failure notice of a Schedule write a Write-back instead. Before Delivery, the Model Turn replaces its Turn progress with the steps of the finished run, so recovery reads the same steps and stores the same bytes (decision 0034).
- **Fired Schedule**: the one module that handles a `ScheduleFired` Event: it reads the Schedule once, checks that it is still due, applies the lateness rule for its Action, sends the text of a Reminder or runs the Budget check and a Model Turn for a Scheduled Task, completes the Schedule, and recovers after a reset through the Delivery state. The Turn loop only routes Events to it.
- **Turn progress**: the steps of a running Turn and the Turn Context Block that it sent, kept so that a Turn after a restart or a reset continues and recovery stores the same bytes. Code deletes the Turn progress of an Event when the Inbox settles it (decision 0033).
- **Conversation**: the stored model history of the main chat of one Owner, which the request of an Owner message Turn starts with. Decision 0033 makes it append-only: it holds the Owner messages with their Turn Context Block, the steps and replies of the agent (with Stubs, and each tool call as a `tool-call` and `tool-result` pair), Write-backs, Approval lines (the line of an `untrusted` Pending Approval names only its id, the tool, and the status), and the one Summary. Each row records its Turn Event id and a row kind, and every row is sent, with no window. It is shortened only by Compaction. It is not the Owner Channel Conversation. [#182](https://github.com/kacperborowieckb/billy/issues/182) builds the terms of decision 0033.
- **Owner Context Block**: the one message after the tool definitions that holds the data of an Owner that changes rarely: the Profile, the time zone, and the MCP Connections with their states. Code writes it and replaces it only when its content changes (decision 0033).
- **Turn Context Block**: the text that code writes at the start of a new Owner message: the current time and the situation of the Turn (open Pending Approvals, the connected Proactive Message, a Restart note). It is stored in the Conversation as it was sent (decision 0033).
- **Compaction**: the one step that shortens the Conversation: it replaces the oldest block of delivered Turns with the Summary. It runs after a Turn when the history is over a token limit (the input token count that the provider reported), as the Model Task `compaction` with no tools, and an Owner message stops it (decision 0033): the Turn goes first and code writes nothing, but the stopped model call runs to its end and records its Usage and its `model_step` point, because the provider bills it ([#217](https://github.com/kacperborowieckb/billy/issues/217)). The rows that the Summary replaces are marked as compacted, are never sent to the model again, and are deleted when the retention period has passed since their Compaction (decision 0034). The request sends an output token limit equal to the Summary limit. It asks for a Summary of at most 60% of the limit ([#223](https://github.com/kacperborowieckb/billy/issues/223)). The model condenses the old Summary first: it keeps the durable facts (facts about the Owner, open commitments, decisions) and drops detail that is no longer needed. Code refuses a Summary that is over the limit or that the limit cut. Then it asks once more for a Summary of at most 30% of the limit. When code refuses both, it records the latest end of a refused block and makes no `compaction` call for a block that ends at or before that row ([#216](https://github.com/kacperborowieckb/billy/issues/216)). The model writes no ids and drops small talk and the detail of finished work. Code then adds the open items to the Summary (decision 0035).
- **Summary**: the one text in the Conversation that stands for all compacted chat. It has two parts in one row. The first part is the prose that the model wrote. Each Compaction writes new prose from the old prose and the block, with no ids. The second part is the list of open items that code reads from storage at the Compaction. It names the Notes with an open Open Loop, the active Schedules, and the open Pending Approvals. The list holds only ids and fields that code writes, for example due times and tool names. It has at most 10 items of each kind (decision 0035). The output limit of Compaction applies only to the prose. It is short memory, not a Note, and a Forget deletes it. It does not make a Turn `untrusted`, because its input, the stored Conversation, holds no Untrusted Content and no model text of an `untrusted` Turn: code stores those as Stubs (decision 0033).
- **Stub**: the short text that code writes in the Conversation in place of content that later Turns must not read in full: Untrusted Content in an input, the reply text of a Turn that was `untrusted` (until [#251](https://github.com/kacperborowieckb/billy/issues/251)), the sent text of such a Side Session, a large tool result, and each tool result of an `untrusted` Turn. The Turn that received the content saw it in full; later Turns see only the Stub. A tool call is stored as a `tool-call` and `tool-result` pair, and the Stub is the result, never text of an agent step (decision 0038). In an `untrusted` Turn, code also replaces each tool-call input and each call id with a value that code writes, and keeps no step text of the model. The Stub of a tool result names the tool, the status, counts, Note ids, the ordered MCP result ids that match the id shape of the MCP Catalog entry (decision 0034), the Connection and the tool of an MCP call from the MCP Catalog, and the Trace of the Turn, so it holds no text from the content. A large tool result is one above `maxStoredToolResultCharacters` of the Behavior Config.
- **Stub reply**: a reply of the model that holds only Stubs. Code never sends or stores it, and runs the model step again, at most `maxStubReplyRetries` times (decision 0038). A Turn that stops at the refusal limit of Auto-review is the exception: code sends no text of the model, only its fixed line, and runs no new model step (decision 0039).
- **Side Session**: the own request of a Scheduled Task Turn or a Proactive Turn. It never holds the main history: it has the system text and the tool set of its Turn kind, the Owner Context Block, and a Run block (decision 0033). It follows its Trust Level like an Owner message Turn. It cannot ask for Approval, so when it is `untrusted`, code writes the prompt of a follow-up that it sets (decision 0034), and every other change, for example a close of an Open Loop, runs only when Auto-review allows it (decision 0039). It gets `find_mcp_tools` and `call_mcp_tool` for `read` MCP calls only: every MCP result and every definition that is not a Pinned Tool Definition is Untrusted Content, so a Side Session that read one of them from a connected server is `untrusted`, and its Write-back names the Connection that it read (decision 0036).
- **Run block**: the one input message of a Side Session that code writes: the current time, the last few Owner and agent text messages of the Conversation (`sideSessionRecentChatMessages` of the Behavior Config), the situation of the run (the set-at time of a Scheduled Task, or the Open Loops in reach with recent Outcomes and mutes), and then the stored prompt, labelled as not a message of the Owner. Turn progress keeps it like the Turn Context Block, and a run that resumes after a reset sends the recorded block again, so its Trust Level and its Write-back do not change.
- **Write-back**: the one assistant message (row kind `write_back`, or `write_back_stub` when it holds the Stub) that a Side Session, a Reminder, a skip notice, or a failure notice of a Schedule appends to the Conversation: a code marker with the kind (Brief, Follow-up, Scheduled Task, or Reminder) and the local due time, the text that the Owner got, and a line that code writes about the changing tool calls that succeeded (a repeated call that changed nothing is left out) and the tools that the run read. Code keeps the marker of a fired Event in Turn progress when it first handles the Event, so recovery writes the same marker after a change of the Schedule or the time zone. It holds no stored prompt, no tool result, and no `role: "user"` text, and a run that sent nothing writes nothing. A run whose Run block, steps, or sent text hold Untrusted Content writes a Stub in place of the sent text, and the connected Owner message Turn reads the row kind, not the text, to decide that the sent text is untrusted (decision 0033).
- **Delivery**: the record of the one outcome that the agent delivers for a Turn (for an Owner message Turn, for its Burst, keyed by the Turn Event; a reply or a reaction goes to the newest message of the Burst), and its state. The outcome kinds are `reply` (a text message), `reaction` (one emoji on the newest Owner message, with no text; the model chooses it with `react`), and `silent` (no Channel call, for small talk such as "ok"; the model chooses it with `stay_silent`). The states are `Unsent`, `Sent`, `Silent`, `SendFailed`, `Unconfirmed`, `ReactionUnconfirmed`, or a failed Event with a notice that is pending, sent, refused, or unconfirmed. `Silent` is final: recovery never sends for that Event, and the other Events of its Burst are done. A reaction is one send with the same states as a text; an unconfirmed reaction is sent once more, in the Turn or by recovery after a reset to the message its plan recorded, because setting a reaction twice gives the same result. The newest of the reaction plan and the text plan decides the state. Code refuses silence in a Turn that changed Owner data or in which a changing tool call failed, refuses a reaction in a Turn in which a changing tool call failed, refuses both in a Turn with a call that waits for Approval (that Turn replies with the Approval buttons), and a failed model call always sends the honest failure text. The outcome kind is not the Outcome of a Proactive Message. Only the Delivery module reads and writes the delivery Journal Entries.
- **Outcome tool**: a tool that the model calls to end a Turn with an outcome other than a text reply, such as `stay_silent` or `react`. It does nothing by itself: code decides the call after the tool loop, and a refusal goes back to the model as the tool result (decisions 0021 and 0023).
- **MCP Connection**: one Owner's link to one MCP Catalog server, with its state: `authenticating`, `ready`, `failed`, or `needs sign-in`. An Owner has at most one MCP Connection for each catalog entry.
- **MCP Catalog**: the Operator's typed list of supported remote MCP servers, in code. Each entry fixes the server URL, the Risk Class of each known tool, the pin of each reviewed tool definition, and the shape of the ids in a result.
- **Pinned Tool Definition**: a tool definition (name, description, input schema) of an MCP server whose fingerprint equals the one that the Operator reviewed and added to the MCP Catalog. It is trusted. Any other definition is Untrusted Content, and a call of that tool is `approve`. When the definition of a pinned tool changes, code writes one Journal Entry (decision 0036).
- **Owner proof link**: a Channel capability. The Channel sends a button whose link proves to the Edge which Channel Identity pressed it. The Telegram Channel implements it with a `login_url` inline button. A link that the Owner forwards proves nothing for another person.
- **MCP Hub**: the Durable Object for one Owner that owns the MCP Connections and the MCP client. It connects a server only on the first call for it, and it keeps the OAuth tokens sealed at rest. The Personal Agent calls it only through RPC.
- **Helper**: a durable workflow that does long or expensive work outside the chat Turn and returns only its result. Not in the MVP.

## Primitives

- **Channel**: an adapter between the agent and the Owner (for example Telegram). It receives messages and turns them into Events. It shows the agent's one send action in its own way (a text or a reaction), and the typing signal (Acknowledge) while a Turn for an Owner message runs. The Channel keeps the list of reactions that it allows, and a close match for some emoji that are not on it.
- **Channel Identity**: the Owner's identity inside a Channel, for example a Telegram user id. The Directory maps it to an Owner Id.
- **Event**: a signal that wakes the agent: an Owner message, a fired Schedule, an `ApprovalAnswered` Event, a finished Helper, or a webhook. Every Event enters the Inbox. An `ApprovalAnswered` Event carries the Owner's answer to a Pending Approval from a Channel button. Code answers the press, records the answer, and runs an approved call with no model call. It is not an Owner message, so it does not join a Burst and does not cause a Restart. When the approved call settles, one reply Turn keyed by the Event answers the Owner from the outcome (decision 0027).
- **Inbox**: the queue of Events for one Owner. The router drops duplicates (an `ApprovalAnswered` Event by its callback query id), merges the pending Owner messages into one Burst once the Quiet Gap passes, and puts Owner messages and `ApprovalAnswered` Events first.
- **Quiet Gap**: the time with no new Owner message (`burstQuietMillis`, default 2500 ms) after which a waiting Burst is answered. It is not Quiet Hours.
- **Owner Channel Conversation**: the Channel and the conversation id where the Owner last wrote. The agent sends there when it has no message to reply to. The Personal Agent keeps it from the Owner's messages.
- **Schedule**: a wake-up time with one Action.
- **Action**: what a Schedule does when it fires: `SendText` or `RunPrompt`.
- **Reminder**: a Schedule that the Owner asks for, with the `SendText` Action.
- **Scheduled Task**: a Schedule with the `RunPrompt` Action. The Owner sets it, or the agent sets it for itself (`setBy: agent`); a Schedule that the agent set is a Proactive Message when it fires.
- **Document**: something the agent writes, for itself or for the Owner. A Note is the main kind.
- **Note**: a small, linked unit of memory with metadata: source, trust level, and the date it was last checked.
- **Open Loop**: something that the Owner or the agent expects to come back to. Optional metadata on a Note: a kind (free text, for example task), a state (`open`, or `closed` with the reason `done`, `dropped`, or `replaced`), an optional due date, and (later) the Schedules that check on it. A fact has no Open Loop.
- **Profile**: the short core facts and style rules about the Owner. The agent adds them to every Turn, and compaction never drops them.
- **Skill**: repeated work saved for reuse, with the tools it names. Loaded only when needed. Not built. The workflows spec ([#187](https://github.com/kacperborowieckb/billy/issues/187)) decides its first form.
- **Journal**: the append-only log of every action and its result for one Owner. The agent reads it and cannot edit it.
- **Journal Entry**: one record in the Journal.
- **Tombstone**: the Journal Entry that a Forget leaves: what was deleted and when, without the content.

## Behavior

- **Capture**: the Owner sends something to keep (a note, task, link, or Reminder). The agent files it as Notes and links it.
- **Recall**: the Owner asks, and the agent answers from its Notes and Journal, and names the source.
- **Forget**: the Owner asks to delete something. The content is deleted for good, and the Journal keeps a Tombstone.
- **Brief**: the daily Proactive Message about what matters today. It is a `RunPrompt` Schedule with `setBy: agent`, that code creates when the Owner's time zone becomes known.
- **Proactive Message**: a message from a Schedule that the agent set (`setBy: agent`). Owner-set Reminders and Scheduled Tasks are not Proactive Messages. Every Proactive Message records an Outcome.
- **Follow-up**: a Proactive Message about one or more Open Loops, from a Schedule that the agent set.
- **Merge**: when the gate sends a Proactive Message, it takes every other agent Schedule with a prompt (not the Brief) that is due within the merge window (default 30 minutes) into the same Turn, so the agent writes one message that counts as one send for the Budget. A follow-up that is due when the Brief is due within the window folds into the Brief.
- **Outcome**: what the Owner did with a Proactive Message: `acted`, `replied`, `muted`, or `ignored`. Code connects the next Owner message to the last Proactive Message, when it comes within the response window. An Outcome is recorded once.
- **Behavior Config**: the typed defaults for each Instance (texting style, quiet hours, budgets, proactivity limits, the default reaction, the Burst wait and restart limits, the token limits of Compaction, and the retention period of Traces).
- **Owner Preferences**: values in the Personal Agent that override the Behavior Config for one Owner, for example Quiet Hours or a "less of this" reply. Each stored value records its source (`owner` now).
- **Mute**: the Owner Preference from a "less of this" reply: the Open Loops of a Proactive Message, or their kind. A muted Open Loop gets no follow-up of its own and appears only in the Brief. "Less" means less often, not never; "stop" closes the Open Loop or cancels the Schedule. The Owner can undo it in the chat.
- **Quiet Hours**: the local time range when the agent sends no Proactive Messages (default 22:00 to 08:00). Code holds a Proactive Message that is due in Quiet Hours and moves it to the end of Quiet Hours. The Owner changes them in the chat, and the stored value records its source. Reminders and Scheduled Tasks that the Owner set still arrive.
- **Budget**: the limit on Proactive Messages per local day (sends, not items) and on tokens for background work, for each Owner. The Owner can change the send Budget in the chat. A follow-up over the Budget folds into the next Brief, and the Brief always runs.
- **Acknowledge**: the instant receipt signal (a reaction or "typing") that the Channel shows before the model runs. Telegram shows "typing" (`sendChatAction`) once for each Owner message of a Burst that waits for its Quiet Gap, and from the start of the Turn of an Owner message until its outcome is sent. It is best-effort and is not a Delivery.

## Safety and quality

- **Risk Class**: the class that code gives to a tool call: `read` (it never changes Owner data), `change` (it runs in an `owner` Turn, and Auto-review checks it in an `untrusted` Turn), `approve` (it always needs Approval, and Auto-review never allows it), or `blocked` (it never runs, and the model gets the reason). Each tool declares one. A tool can also give a function from its input to a Risk Class, which can only raise the declared class. The model never sets it. The gate decides each call from its Risk Class, the Trust Level of the Turn, and whether the Turn can ask the Owner for Approval (decision 0027). A Side Session cannot ask, so in an `untrusted` Side Session a `change` call runs with an input that code writes when its tool has one (the fixed follow-up prompt of `set_schedule`, decision 0034). Otherwise it runs only when Auto-review allows it, and is denied for every other answer (decision 0039).
- **Pending Approval**: one frozen tool call that waits for the Owner's answer, with its summary, its state, and its expiry. Code writes the summary; the model never writes it. When Auto-review answered `ask`, its short reason is a separate line under the summary until the Owner answers. A call whose input contains an Operator secret never becomes a Pending Approval; the model gets a refusal, so the stored frozen input is always the exact input. It starts as a draft and becomes `pending` only when the Delivery of its Turn is `Sent` or `Unconfirmed`; a Restart, a failed model call, or a failed send deletes the drafts, so the Owner never gets a Pending Approval that they cannot see. A `pending` one that the Owner does not answer expires at its expiry instant (the expiry of its tool, else the Behavior Config default of 24 hours): code sets it to `expired` with no model call, the Approval message shows "Expired", and a later press runs nothing.
- **Approval**: the Owner's answer to a Pending Approval: approved or rejected. The Owner gives it only with a Channel button; a text message never answers a Pending Approval. Code runs an approved call once, with the exact input that code froze. Then one reply Turn gets the call and its outcome (`executed`, `failed`, or `unconfirmed`) as a completed step and answers the Owner in a new message.
- **Auto-review**: a separate reviewer model that checks a `change` call of an `untrusted` Turn before the Owner sees it (decision 0039). Code gives it only the Owner's own messages (the Burst and the recent earlier ones, never a forwarded text), the tool and its frozen input, and the local times: never a tool result and never text that the model wrote. It answers `allow` (the call runs with no tap), `ask` (a Pending Approval, with the reason of the reviewer under the code summary), or `refuse` (the call does not run, and the model gets the reason). A failed, late, or invalid review is `ask`, so it never fails open. After several refusals in one Turn, code runs no more changes in it and sends the Owner only a fixed line. In a Side Session only `allow` runs the call. It never reviews an `approve` call. Its Model Task is `auto_review`.
- **Trust Level**: the mark on a Note, an Event, and a Turn that says where its text came from: `owner` for the Owner's own words, `untrusted` for Untrusted Content. Code sets it from the Event and from the stored data, never from the model. A Turn is `untrusted` when its Burst, its Turn Context Block, or the stored prompt or Run block of a Side Session has Untrusted Content, when an open Pending Approval of an `untrusted` Turn is listed for it, or when a tool result in the Turn returned Untrusted Content; it never goes back to `owner` in the same Turn. The stored history holds only Stubs of Untrusted Content, so code does not read it for the Trust Level (decision 0033).
- **Untrusted Content**: text from outside the Owner's own messages (forwarded messages, web pages, mail, webhooks, tool output). It is data and never an instruction.
- **Trace**: the record of a Turn: a pointer to its request, tool calls, results, cost, latency, and cache hits. Enough to replay the Turn. The pointer holds hashes of the system text, the tool definitions, and the Owner Context Block, the range and hash of the Conversation rows that the request sent, and in full only the new tail (decision 0034). Code keeps each version of the three parts under its hash, and replay reports a part that is missing or changed. Code deletes a Trace after the retention period of the Behavior Config (`traceRetentionDays`, first value 30 days, never below the floor of 7 days).
- **Eval**: a repeatable case that scores the full sequence of steps of a Turn. Measured as pass^k: it passes on every one of k runs.
- **Eval Case**: one Eval: the Notes and Profile entries to seed (optional), the Owner Events to send, and the checks on storage, the Trace, and the replies.
- **Judge**: the model that checks the replies of an Eval Case against the fixed rubric of the case. It is its own Model Task, `eval_judge`.
- **Usage**: the tokens, messages, and cost for each Owner. Code records one row for each model step, with its Model Task and the Event of the request, so Compaction reads the input tokens that the provider reported.

## Model

- **Model Gateway**: the one interface to all model providers. It picks the route of each Model Task from the Model Route table, and the credentials for the Owner.
- **Model Route table**: the one configuration of models (`MODEL_ROUTES`, decision 0034): a primary, a secondary, and a reviewer route, each a model and a reasoning effort, and for each Model Task which of them it uses. Every Model Task has a row; there is no default route.
- **Hit Rate**: the cached input tokens of a model step divided by its input tokens. Step 1 of a Turn shows reuse of the earlier Turn, and later steps show reuse inside the Turn. A miss that code did not plan is a bug (decision 0033).
- **Planned miss**: a cache miss of step 1 that code knows the reason for: no earlier call of the session, the first call after the cache lifetime (60 minutes), a deploy that changed the system text or a tool definition, a changed Owner Context Block, the first call after a Compaction, or a Stub in the Turn before (decision 0033; a Forget comes with #138). The Operator metric records the reason, and `pnpm control doctor` counts only the calls with no planned miss.
- **Session affinity**: the `x-session-affinity` value of every model call: one opaque id for each Owner, a hash of the Owner Id, the same for the main Conversation and the Side Sessions (decision 0033).
- **Model Credentials**: what the Model Gateway uses to call models for one Owner: the AI Gateway token and the billing mode. A self-host Instance uses Unified Billing with the Operator's Cloudflare credits by default, or the Operator's own provider key (BYOK). The hosted product uses the platform's credits and bills the Usage.
